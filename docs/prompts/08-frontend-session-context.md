# Context for a new session working in the frontend repo

Paste this at the start of a fresh Claude Code session opened in the
`ai-interview-coach-frontend` repo, so it has the context of the broader project without
needing to rediscover it.

## What this project is

**AI Job Interview Coach** — a hackathon project. A user uploads their CV (PDF) and pastes a
job description; the app analyzes the fit, generates a personalized 8-question mock interview
(technical/behavioral/HR), runs it as a chat-style interview with live scoring and follow-up
questions when an answer is vague, and produces a final AI-written readiness report (score,
strengths, weaknesses, a study plan tied to the candidate's actual skill gaps).

## Repo split

Two separate repos, two separate deploys:

- **Backend** (Python/FastAPI): [`ai-interview-coach-backend`](https://github.com/kariniskandarani/ai-interview-coach-backend)
  — the actual AI pipeline, fully built, tested (48 offline tests), and live-verified against
  the real APIs it depends on. Deployed on Render.
- **Frontend** (this repo, Next.js/React/TypeScript): generated via Replit's AI Agent from a
  series of prompts, then exported here. Calls the backend over HTTP — **does not
  reimplement any AI/business logic**.

## The API contract, and how the frontend was actually built

The frontend wasn't hand-coded here — it was generated by pasting a series of prompts into
Replit's AI Agent, each scoped to one concern, then exporting the result into this repo. **All
of these prompt files live in the backend repo** and are the authoritative record of what was
asked for (including the full API request/response contract for every endpoint):

1. `docs/prompts/01-frontend.md` — the original build: BRD/PRD, marketing copy, full API
   contract, tech stack requirement (Next.js/React/TypeScript/Tailwind).
2. `docs/prompts/02-visual-polish.md` — visual design pass (color, typography, hero section).
3. `docs/prompts/03-history-and-resume.md` — resume-an-interview-after-refresh (via
   `localStorage` + `GET /api/sessions/{id}`) and a "Past Interviews" history page.
4. `docs/prompts/05-ux-polish.md` — staged loading states, a real completion-screen payoff
   (score visualization), chat interaction polish (auto-scroll, Enter-to-submit).
5. `docs/prompts/06-sizing-refinement.md` — reduced answer-input-box height, tightened the
   session header/progress bar.
6. `docs/prompts/07-report-feature.md` — the final AI-written report feature
   (`GET /api/sessions/{id}/report`), added after the backend endpoint was built.
7. `docs/prompts/04-auth.md` — Supabase Auth (email/password login + a "Try Me" guest path
   that skips login and doesn't save history), including the real Supabase project URL and
   publishable key the frontend needs.

**Important: only *some* of these have actually been applied and re-exported into this repo
so far — which ones is not precisely known right now.** Before doing any new work, inspect
the actual code in this repo to determine what's really implemented (e.g.: is there
`localStorage` session-id handling? a history page? a login/signup form calling
`@supabase/supabase-js`? a report view calling `/report`?) rather than assuming any prompt's
changes are already present. Treat the numbered list above as "the full intended feature set
and its exact spec," and the repo's actual code as "ground truth for what's done" — diff
between them before proceeding.

## How to work with this user

- They're learning AI app development hands-on — Python-competent, newer to frontend/AI
  architecture. They want to actually understand what's built, not just receive working code.
  Explain concepts before implementing changes, especially anything Next.js/React/TypeScript-
  specific they haven't seen before.
- Prefers small, focused changes over big rewrites — verify things actually work (run it,
  don't just claim it does) before calling something done.
- Time-pressured around a hackathon demo video — be direct about scope/tradeoffs rather than
  over-building.
